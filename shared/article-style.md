# Article style — язык и форма статьи

Правила языка и формы для Title / Writer / Sol.
Живой ритм подачи — в:

1. `shared/SOUL.md`
2. `shared/soul-examples/good-outputs.md`
3. `shared/soul-examples/post-to-article.md`
4. `shared/soul-examples/bad-outputs.md`

Язык тенанта: **русский** (`tenant-config.language=ru`).

## HTML (whitelist)

- Теги тела: `h2`, `h3`, `p`, `<b>`, `<i>`, `a`, списки, таблицы, `figure`/`img` — см. `scripts/excalibur_blog_html_linter.py`.
- **CTA-обёртки:** `<div class="excalibur-cta-early|mid|end">` (опц. `excalibur-social-cta` на end) — единственный разрешённый `<div>` в теле; см. `shared/quality-bar-9.md`.
- **`<b>` не `<strong>`**, **`<i>` не `<em>`** — иначе html_linter FAIL (autofix после Sol как страховка).

## Голос

- Личный риэлтор: «я», «веду сделку», «проверяю до аванса». Не агентство.
- **Ритм Клышина:** короткие абзацы (часто одно предложение), вопрос-крючок, диалог в кавычках, контраст «вижу X / спрашиваю Y».
- Факты и география — **Шакин / Тюмень**: ЕГРН, опека, эскроу, Росреестр, районы, наш.дом.рф.
- Одна мысль за раз. Лишнее — вырезай.
- Ирония через факт («скидка — плата за риск»). Без стендапа.
- Форматы: разбор риска, чеклист, troubleshooting, сравнение (если дал Writer).

## Русский язык

- Избегай англицизмов, когда есть русское слово. ДДУ, ЕГРН, эскроу — как в источнике Writer.
- Допустимы **риэлтор / риелтор** как у тенанта.
- Без канцелярита: «данный», «осуществлять», «является», «в рамках».
- Без штампов: «в современном мире», «полный гайд», «давайте разберёмся».
- Без плашки терминов в лиде. Без эмодзи.

## Заголовок (H1)

- Вопрос или вскрытие схемы: «Почему…», «Что будет, если…», «Кажется чисто — а на самом деле…»
- Одна конкретная мысль. Без SEO-хвостов и «гайд 2026».
- Без «нулевого риска» и «лучший риэлтор».
- Дзен: прямой порядок слов, без кликбейта — `shared/dzen-content-rules.md`.

## Открытие

- Sol владеет финальным открытием.
- Сцена или ставка + зачем читать. Затем **прозаический лид** (4–6 предложений) — часть news-casus, не чеклист.
- **Запрещено в первом экране:** английский TL;DR; блоки «Быстрый инсайт» / «быстрый инсайдер»; bullet-списки `<ul>/<ol>` до первого H2.
- Без research-брифинга.
- **Casus specificity:** конкретный день в комнате; **ban** meta-disclaimer («случай собирательный», «без фамилий», «механика в Тюмени повторяется», «не репортаж»). Не выдумывать реальные ЖК/банк; не объяснять отсутствие имён.

## Структура (longform)

- **~1800–2200 слов** (≈8–10 мин), семантический slug (не daily-timestamp). Hard FAIL > ~2400.
- **Spine once:** один проход casus; практика — **один** блок после финала, без recap-пересказов.
- **5–8 H2** — биты истории и практики; **не** раздувать ради «7 картинок под 7 заголовков».
- Inline `inline_1…7` — **7 PNG всего**, но в HTML допустимы **0 / 1 / пара** на H2 (см. cover canon).
- H2 = бит проверки или место, где теряют деньги.
- Нумерованные чеклисты с глаголами.
- Таблицы — для сравнения условий, не для SEO.
- Финал: предел компетенции, «Материал проверен: Святослав Шакин…», дисклеймер.

## Запреты площадок

- VPN / обход блокировок, RF-blocked heroes.
- Не копировать голос Клышина дословно и не ссылаться на него как на автора.

## Self-check

1. Лид — сцена + крючок, не справочник?
2. Абзацы короткие, есть диалог в кавычках?
3. Есть контраст «обычный взгляд / вопрос профи»?
4. Метод до аванса, без нулевого риска?
5. H1 без SEO-хвоста?
6. CTA после пользы, не в каждом абзаце?
7. Мата и эмодзи нет?
