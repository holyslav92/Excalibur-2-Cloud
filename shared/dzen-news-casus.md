## Comment magnet (обязательно)

Одна **острая вопросительная реплика**, с которой читатели **спорят в комментариях** —
не риторика «подписывайтесь», не FAQ-шаблон.

- Формат: реплика в кавычках «…?» или прямой вопрос читателю с двумя полюсами (кто прав / что бы вы / а вы как).
- Место: после **финала casus** или перед **mid CTA** — когда ставки уже ясны.
- Scout/Title: намечают **угол спора**; Writer/Sol: вшивают один живой вопрос в текст.
- Gate: `comment_magnet_question` в quality-bar-9.

Примеры энергии (не копировать): «Справка хватит?» / «Кто виноват — покупатель или банк?» / «А вы бы внесли аванс, если выписка „чистая“?»

## Формула champion (обязательные элементы)

Каждая новая тема Scout → Writer → Sol должна содержать **все пять**:

1. **Завершённое событие** — сделка/суд/отмена/спор уже случились (не «как купить»).
2. **Именованный риск** — конкретный юридический/денежный риск (ЕГРН, аванс, наследство, доверенность…).
3. **Временная метка** — «через год», «за 48 часов», «на сделке», «через три месяца после регистрации».
4. **Человек, который думал, что всё безопасно** — покупатель/продавец сделал «всё правильно» по своей логике.
5. **Финал** — суд, отмена регистрации, деньги не вернули, квартиру забрали, сделку оспорили.

Без финала в архитектуре текста — **WRITER/SOL FAIL** (урок «Расписку написали»).

Полезная часть («что проверить») — **после** истории, как **разбор последствий**, не вместо неё.

### Casus specificity — no composite disclaimer (owner lock 2026-09-01)

Casus = **конкретный день в комнате** (звонок, офис банка, кухня перед бронью). Анонимизация **молча**:
«семья», «застройщик», «банк» — без реальных названий ЖК/банков и **без** объяснения читателю.

**FAIL в теле:** «Случай собирательный»; «без фамилий» / «без адреса ЖК» / «без названия банка»;
«механика в Тюмени повторяется из месяца в месяц»; любой disclaimer про composite / modeled / anonymized / «не репортаж».
Gate: `no_composite_disclaimer` (`scripts/excalibur_blog_composite_disclaimer.py`).

## Тело статьи (Writer → Sol)

- **~1400–1600 слов** после Sol (≈8–10 мин в Дзене). **Hard FAIL** если **> ~1750** или Дзен покажет **>10 мин**.
- **Spine once (one-breath):** casus проходит **один раз** — лид → развитие → финал → **практика один раз** → agency ending. **Не** пересказывать ту же сцену в лиде, середине и «итоге». **Вырезать:** recap («коротко если некогда»), повтор одних цифр/флагов трижды, lecture-хвосты.
- **Структура:**
  1. Лид-новость: сцена + **прозаический лид** (4–6 предложений, финал в перспективе или намёком). Без TL;DR / «Быстрый инсайт» / bullet-списков в первом экране.
  2. Early CTA (TG+MAX only).
  3. H2 — развитие casus (что пошло не так, хронология).
  4. H2 — **финал** (суд / отмена / деньги).
  5. H2 — «что проверить теперь» (практика **после** новости; ol/таблица ок, но не главный hook).
  6. Mid CTA после практического блока.
  7. End CTA (dual + полный набор).
- **Comment magnet:** один острый вопрос для комментариев (после финала или перед mid CTA).
- Interlink 2–4 sibling — без изменений.

## Ending landing — agency, not panic (owner lock 2026-08-28)

**HOT casus не ослабляем** — stakes, хронология, финал (суд / отмена / деньги) остаются. Меняется **посадка** в последних 1–2 абзацах перед end CTA: читатель уходит с **ручкой**, не с «риск везде — никогда не покупать».

### Default (большинство постов)

Последний эмоциональный beat — **воздух + agency**, не dread:

| Посадка | Пример энергии |
|---------|----------------|
| Остановились до аванса / брони | «На этом шаге бронь сняли — деньги на эскроу не ушли» |
| Проверка спасла | «Одна строка в ДДУ — и аванс не внесли» |
| Новостройка ≠ лотерея | «Каждый день берут — если смотреть договор до денег, а не после» |

CTA (TG+MAX, телефон, end dual) — **«подключусь до аванса»**, не «бегите с рынка».

### Exception (редко)

Жёсткая потеря в casus **OK**, если вилка действия очевидна: «если бы сделали X **до аванса** — не потеряли». **Запрещено** заканчивать чистым ужасом без fork.

### Ban (landing)

- Sugar happy ending, который убивает casus.
- Чеклист из N шагов как **эмоциональный финал** (практический H2 после истории — ок; **последний beat** = story + agency).
- Takeaway «риски везде, как вообще покупать» / «все риэлторы плохие» / «вторичка — мина».

Writer + Sol: см. skills + `shared/quality-bar-9.md` → End landing.

## Примеры gate (Scout)

### PASS

**«Ипотеку одобрили, а регистрацию отменили через полгода: в выписке висела одна строка»**

- событие завершено ✓
- риск: реквизит ЕГРН ✓
- метка: «через полгода» ✓
- «всё проверили до аванса» ✓
- финал: отмена регистрации ✓
- другой plot, не duplicate cluster ✓
- Wordstat: «проверка егрн тюмень» / «выписка егрн» после rework ✓

### FAIL (shape)

**«Чеклист покупки квартиры в Тюмени: 7 шагов без риелтора»**

- forbidden hook «чеклист» / «N шагов» ✗
- нет завершённого события и финала ✗
- how-to вместо casus ✗

### FAIL (duplicate)

**«Наследство не прошло: сын от первого брака так и не отказался — аванс уже внесли»** — если cluster `inheritance_son_first_marriage_no_refusal` уже в ledger/used-clusters за **30 дней**.
